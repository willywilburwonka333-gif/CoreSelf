# Genesis 1.3 — Offline Dylan Core

Genesis 1.3 makes Core Self degrade into a useful local second-self instead of an error screen when cloud AI or internet access fails.

## Added

- A deterministic Offline Dylan Core grounded in the confirmed Identity Core, private Seed Vault, retrieved memories, projects, goals, plans and prepared actions.
- Rule paths for identity, family, priorities, memory, projects, goals, decisions, coding and creative work.
- A service-worker app shell so a previously opened production build can start without the network.
- Remembered-device offline access after a successful Firebase login.
- Visible `Offline Core` status and automatic recovery when connectivity returns.
- A permanent Wilbur Wonka Music Core covering artist/studio identity, human-led AI-assisted process, signature sound, songwriting constraints, catalogue, seven-persona system and public channels.
- Music/Wilbur questions now route to creative identity online and offline even when the separate private Seed Vault has not been imported.

## Safety

- Offline mode cannot claim live research, deployment, generation or external actions.
- Spending, publishing, deleting, sending and production changes remain behind approval gates.
- Permanent identity changes continue through the confirmation flow.
- Private context remains in browser storage and is not committed to the public repository.

## Limits

- Genesis 1.3 is a rule engine, not a locally hosted language model.
- Advanced generation and open-ended reasoning resume when a configured provider returns.
- The service worker must successfully install once while online before cold-start offline use is available.
